EC2 JSON files 75

The legacy client portal kept 75 reference files on its EC2 host; the business asked for them in the database. Stage 05_ec2_statics (and 87_ec2_links for the two steps that need later stages) places every file deliberately: legacy_source = 'ec2:<path>', the file's sha256 in the stage message, every id in audit.migration_id_map. Where a file is a twin of a database table, the table is authoritative (user decision U10) and the file only produces a diff report. Every file is placed.

How this page is built

  1. Legacy tables and column counts: CREATE TABLE statements in analysis/legacy_mysql_schema_261013.sql.
  2. Every Stage(legacy=…, target=…) in etl/stage_*.py; loop variables are resolved statically (for-loops over literal lists or dicts, spec["table"], next(t for t in (…)) name probes). SQL text naming a legacy table counts as a read.
  3. MAPPINGS, CONSUMED_AS_REFERENCE and NO_TARGET_REASON from etl/mapping_spec.py; EXCLUDED_TABLES from etl/config.py.
  4. Precedence: a stage that writes a real target → migrated (unless excluded); excluded or ledger-only → excluded; a recorded reason → no target; reference list or SQL read → reference; otherwise unaccounted.
  5. Targets link to the schema guide only when the live v3 catalog (docs/_catalog.json) has the table.
